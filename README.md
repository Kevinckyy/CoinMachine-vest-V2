# Vest Fleet

Vest 多节点、多账户控制系统。中心维护账户目录和策略，云服务器上的桥持久化指令，Chrome / Edge 插件在已登录的 Vest 页面执行浏览器操作。参考旧项目迁入了账户菜单、桌面持仓表、市价表单、原生止盈止损和 Live 利润领取流程。中心和桥使用 Python 标准库与 SQLite，控制台和插件均可直接从源码运行。

```text
管理浏览器 ── HTTPS ── 中心控制台 / 决策服务 ── 中心 SQLite
                           │
                           ├── HTTPS ── 节点 A 的桥 ── 节点 SQLite
                           │                ├── 本机插件 / 浏览器一 ── 多个 Vest 账户
                           │                └── 本机插件 / 浏览器二 ── 多个 Vest 账户
                           └── HTTPS ── 节点 B 的桥 ── 本机插件 ── 多个 Vest 账户
```

## 本机启动

需要 Python 3.12+ 和支持 Manifest V3 的 Chrome 或 Edge。下面用两个 PowerShell 窗口在同一台机器启动中心与一个节点。两个窗口均在本项目根目录运行。

**窗口一 · 中心**

```powershell
$env:VEST_ADMIN_TOKEN = python -m fleet key
$env:VEST_ADMIN_TOKEN
python -m fleet center
```

打开 [本机控制台](http://127.0.0.1:8780/)，用上一步生成的管理密钥登录。

**窗口二 · 节点桥**

```powershell
$env:VEST_NODE_ID = 'cloud-01'
$env:VEST_NODE_TOKEN = python -m fleet key
$env:VEST_PLUGIN_TOKEN = python -m fleet key
$env:VEST_NODE_TOKEN
$env:VEST_PLUGIN_TOKEN
python -m fleet bridge
```

1. 在中心点击「添加服务器」。节点 ID 填 `cloud-01`，桥地址填 `http://127.0.0.1:8877`，节点通信密钥填 `VEST_NODE_TOKEN`。
2. 在节点机器打开 `chrome://extensions` 或 `edge://extensions`，启用开发者模式，加载本项目的 `extension/` 目录。每个独立的浏览器配置文件各加载一次。
3. 在浏览器中打开已登录的 [Vest 活动账户页](https://next.vestmarkets.com/accounts)。打开插件，填写浏览器名称和 `VEST_PLUGIN_TOKEN`，点击「绑定为只读」。安装或重新加载插件前就已打开的 Vest 标签页，可直接在原页绑定。首次绑定后，活动卡片清单会存入浏览器缓存和节点桥。
4. 在「账户与持仓」选择节点，查看该节点的账户、净值、浮动盈亏和持仓。「管理」可维护别名、备注、交易账户标识、执行开关和策略池。「指令」可下发读取操作，包括「同步订单与盈亏历史」。返回值可在同一节点的「指令记录」查看。
5. 首次在节点插件中绑定 Vest 标签页。此后可以在控制中心「服务器 → 浏览器 → 权限」为该浏览器选择「切为执行」或「切为只读」，也可以使用插件上的按钮。权限列显示插件实际模式，切换期间会显示「等待插件确认」。策略已启动时，切为执行后可以按原参数开仓。浏览器重启后需要重新绑定。

密钥生成命令用于首次配置。后续启动时，从密码管理器或服务环境恢复同一组密钥。中心数据默认位于 `runtime/center.sqlite3`，每个节点使用自己的 `runtime/bridge.sqlite3`。可通过 `--db` 更换数据路径，`--host`、`--port` 更换监听地址。插件使用节点机器的 `127.0.0.1:8877`。

## 分布式部署

需要由中心统一发布节点桥和浏览器插件时，请按[节点自动更新部署指南](deploy/UPDATES.md)完成首次接入。之后在控制台的「服务器 → 节点更新」选择节点和 Git 提交即可发布。每个节点的桥版本、浏览器实际加载版本和执行回执单独展示。

每台云服务器使用独立节点 ID、独立节点密钥、独立插件密钥和持久化卷。浏览器运行在对应节点的桌面会话内，保持绑定的交易标签页处于可运行状态。中心通过节点的 HTTPS 地址拉取状态并投递指令，节点插件只需访问回环地址。多台机器需保持系统时钟同步。

**Linux 中心主机**

在项目目录准备环境文件，例如 `center.env`，写入本机域名和生成的管理密钥。将域名 DNS 指向该主机，为 Caddy 开放 TCP 80、443。

```dotenv
VEST_DOMAIN=control.example.com
VEST_ADMIN_TOKEN=<独立生成的中心管理密钥>
```

```sh
docker compose --env-file center.env -f deploy/center.compose.yml up -d
```

**每台 Linux 浏览器节点（手动部署模式）**

在节点项目目录准备 `bridge.env`，将该节点的域名指向本机，并开放 TCP 80、443。

```dotenv
VEST_DOMAIN=bridge-01.example.com
VEST_NODE_ID=cloud-01
VEST_NODE_TOKEN=<该节点的中心通信密钥>
VEST_PLUGIN_TOKEN=<该节点的插件密钥>
```

```sh
docker compose --env-file bridge.env -f deploy/bridge.compose.yml up -d
```

Caddy 为域名提供 HTTPS，公网桥转发状态、历史与日志增量、中心指令接口。宿主机的 `127.0.0.1:8877` 供插件连接。回到中心，用节点的 HTTPS 根地址登记。Windows 云桌面也可按本机步骤运行原生桥，再用 HTTPS 反向代理转发 `/v1/status`、`/v1/ledger`、`/v1/logs` 和 `/v1/commands/*` 到 `127.0.0.1:8877`。

中心数据库保存各节点的通信密钥，数据库、卷和环境文件应只对服务管理员可读。备份可使用 SQLite 在线备份，或停服务后复制数据库及同目录 WAL 文件。中心固定记录首次连接的节点数据库身份。桥数据丢失时，应恢复原库，或使用新的节点 ID 和地址重新登记，以便隔离旧库中的在途指令。

## 账户、策略和回执

- 每个账户快照均带节点、浏览器、平台完整账户名和读取时间。桥断连、插件离线、账户消失、读数过期分别显示。历史净值和持仓保留时间戳，只有新鲜且确认的持仓计入总览。
- 中心按**交易账户标识**共享未完成指令和每日开仓额度，默认使用平台完整账户名。同一实际账户出现在多个节点时，保持相同标识；不同登录下的同名账户可在「管理」中指定各自的标识。浏览器菜单内部同名且无法区分的条目仅显示。主账户持续保留只读属性。
- 「自动策略」列出所有节点。每张卡片分别统计考核 1/2、考核 2/2 和 Live 账户，绿色表示执行中，蓝色表示在线，红色表示离线。阶段待确认的账户单独计数。点击卡片可查看本节点的候选账户、池外账户、风控指标、持仓和本批指令。卡片上的启停与参数设置只作用于该节点。
- 在「自动策略 → 默认参数」设置新登记节点的初始值。「参数预设」支持新建、编辑和删除命名方案。停止节点策略后，打开卡片上的「参数设置」，选择中心默认参数或预设，检查数值并保存到此节点。已有节点保留各自保存的参数。
- 三个参数表单均按当前选择显示可用字段。动态分配时，设定有限的 Live 池上限会显示候补下限与恢复线，Live 池不限时显示目标存量。选择定额领取会显示金额，按比例领取会显示百分比。考核与 Live 的免止损阈值随各自的开关显示。
- 选池沿用原项目的全随机、每批同阶段和动态分配，支持阶段顺序、各池上限、动态候补与考核补位名额。初始每批 2 户，批内等待 2–8 秒，批间等待 15–45 秒。考核 1/2 和 2/2 分别设置仓位，开仓时清空止盈。混合批次遇到相反的固定方向会在发单前暂停。
- 节点桥将浏览器会话变化、账户读取异常与恢复、持仓变化、指令状态和操作许可写入本机日志。中心按游标补传，在「运行日志」中标明事件来自节点桥或控制中心。浏览器的普通心跳不会重复生成日志。
- 新节点的策略初始为停止。启动前，中心要求节点的在线浏览器全量拉取账户列表，再按本次清单选取已授权、空仓且符合风控的候选账户。运行中发现的新活动账户按相同规则参加后续选择。手动排除、停用和同名冲突会阻止选用。每批统一方向，各节点独立运行。
- 「全量拉取账户列表」复用 `/accounts` 页面收到的完整活动账户响应，按平台账户 ID 合并卡片名称和监控数字。仅完整且有效的清单可以移除旧账户。策略启动、手动拉取和购买成功都会触发这一步。消失的账户退出活动池，历史和管理设置保留。日常监控使用卡片上的持仓数、浮盈亏、日损和回撤。
- 「全量读取账户信息」在 `/accounts` 复用网页已收到的活动账户、余额、挂单、持仓和净值序列响应。插件按平台账户 ID 合并一次全表，缓存确认后返回结果。净值取近期平台采样，或在已确认空仓且无挂单时取余额。健康度按 Vest 的日损和回撤占用比例计算。缺少的数据列在各账户的 `missing` 中；清单不完整时保留旧缓存。开仓前仍单独核验所选账户。
- 在中心的「账户与持仓」可对所选节点的在线浏览器下达以上指令，并查看完整、字段不全和失败的账户数。在「下达浏览器指令」可指定一个浏览器，也可在该浏览器的插件弹窗发起。两项读取均支持只读绑定。
- 同一账户、同一阶段每个美东交易日有一次常规开仓额度，美东 20:00 日切。Live 账户经当前策略核验的利润扣款可解锁一次再入场。整批指令成功、持仓确认结束且领取处理完毕后，该节点进入批间等待。失败或结果未知会暂停该节点的策略。停止策略会取消尚未领取的本批指令。
- 已成交的账户从活动列表消失，或持仓数超过 30 秒没有有效读数时，中心会让对应浏览器全量拉取账户列表。同一浏览器上同时待核对的账户共用一次读取。插件 1.11.2 从本次页面加载的活动账户和持仓响应按平台 ID 核对。读数中断期间保留本批，确认账户空仓或原账户已移出后，继续等待同批其余持仓和已发起的 Live 领取回执。进入批间等待后，节点卡片和详情页按中心安排的下一批时间逐秒倒计时。
- 自 1.11.3 起，运行中的节点策略可处理 Vest 的中英文考核结果提示。一阶段通过后等待「开始下一阶段」就绪，二阶段通过后使用「前往 Funded Account」。节点日志记录操作，插件核验同一考核链的新阶段及空仓后重新拉取账户列表。已关闭账户的亏损上限提示仅使用关闭按钮。暂停策略或切到只读会保留提示供人工处理。遇到其他风险确认、叠加弹窗或无法核验的阶段结果，可在节点运行日志查看原因。
- 中心和桥都在发送前落盘。中心重发时使用相同指令 ID，桥对每个资金操作步骤只签发一次许可，插件在点击前也持久记录该许可。已签发许可但执行超时，或在途资金指令因节点失联超过执行时间窗时，指令进入「待核验」，同一交易账户的新资金操作会被拦住。节点恢复后会核对原账本。原会话的迟到回执可补全结果，操作员也可在指令详情中根据平台记录填写核验结论。
- 开仓前插件进入 NQ-PERP 交易页选择目标账户，以实读的健康度、日损、最大回撤、净值、阶段和持仓状态更正缓存。同账户同阶段仍合格时继续原指令，提交前再次核对，保护金额变化时重新填表。触及风控条件时锁定至下一次美东 20:00，策略为同批补选。身份或底线暂未读全时，45 秒后可重新核验。账户和策略详情显示原因及到期时间。手动仓位使用 Micro 合约数（1 Micro = 2 Vest 单位），策略仓位使用平台百分档。
- 开仓时复用 Vest 页面已经收到的活动账户响应，以当前选中账户 ID 读取今日底线和最大回撤线。底线响应最多使用 330 秒，净值等交易页读数最多使用 15 秒。日切或 Live 提现后以新的页面读数为准。需设置止损时，取净值至今日底线的距离和剩余最大回撤（上限减去已用回撤金额）中的较小值，再减去缓冲 M，考核与 Live 的 M 初始均为 **20 USD**。
- Live 止盈可选固定金额、固定盈亏比、当日首次与后续两档。盈亏比模式取风险金额 × 盈亏比和最低止盈金额的较大值，常规风险金额为本单止损金额，免止损时使用净值至页面爆仓线的距离。两档模式按每个账户在美东 20:00 起算的交易日内是否已有确认成交，分别使用对应的止盈额和仓位。固定或分档金额留空时，该档 Live 自动开仓等待配置。升级保留原 Live 固定止盈额，新增盈亏比默认为 1，最低额为 0，两档仓位继承原 Live 仓位。
- 节点默认开启两线差额免止损，考核和 Live 共用阈值 20 USD。交易页「今日底线」减去「最大回撤」提示框中的账户关闭线，差额严格低于阈值时留空止损。原分阶段开关比较账户净值减去最大回撤线。任一已开启的规则命中即免止损，等于阈值时该规则不触发。成交后核对原生止盈和止损，免止损时须确认原生止损为空。需要修正止损价时按实际仓位和 0.25 价格跳动向保留缓冲的一侧取整。
- 「Live 下单与风控」默认展开，首项是「Live 默认锁定」。开启后，可在「管理账户」中为指定 Live 账户勾选「加入自动策略池」以单独解锁。关闭后，符合账户池条件的 Live 账户可自动入池。本轮策略的 Live 持仓平仓后，插件先到 Portfolio 实读可领额。中心据此计算全部、定额或指定比例的领取金额。可领额为零时跳过领取。提交时重新核对页面预览，返回交易页确认源账户的实际扣款后才放行再入场。动态分配在下一批重新选取，其他选池方式沿用本批方向和批内等待。
- 「领取利润」用于从明确空仓的 Live 账户领取指定金额到 Vest 主账户。插件核对持仓页占用、收款对象、可领金额和到账预览，再核验源账户扣款。回执中的 `source_balance_debited` 表示源账户余额已核实，主账户最终到账以平台记录为准。

指令参数、HTTP 路由和轮询方式见 [版本 1 API](API.md)。

## 盈亏分析与订单历史

「盈亏分析」支持按节点、完整账户名、阶段、日期范围和每日时段筛选。日期和时段统一使用北京时间。起止日期都包含在内，时段包含开始时刻，到结束时刻截止。例如只选 11 月 23 日、22:00 至 02:00，统计区间为 23 日 22:00 至 24 日 02:00。此筛选独立于美东交易日的开仓额度。

| 指标 | 计算口径 |
| --- | --- |
| 已实现盈亏 | 汇总平台历史持仓的 PnL，按平仓时间归属。金额单位为 USDC。活动持仓的浮盈亏显示在「账户与持仓」。 |
| 分阶段胜率 | 盈利笔数 ÷ 有明确盈亏的平仓笔数。持平计入分母。仅观测到平仓、尚未读到盈亏的列入「待补盈亏」。未取得阶段依据的记录归入「阶段未知」。 |
| 平台总出金 | 汇总 Portfolio 利润领取历史中状态为已完成、带完成时间和可读净额的记录。以页面显示的净额为准，处理、失败和退款记录可在「平台出金」查看。 |
| 系统已核验扣款 | 累计本系统成功领取、并已核对来源账户扣款的申请毛额。预计到账额另列。相同指令的重传只入账一次。 |

「平台订单」保存平台上的订单编号、合约、方向、数量、成交价、状态和时间。「交易指令」保存中心发出的开仓、平仓和保护指令，可以追踪投递流程。每个节点统计自己读到的数据。全网指标按交易账户标识和记录编号去重，同一账户经多个节点观察时只计一次。

当卡片显示此前有仓位的账户已经空仓，中心会为该账户下发一次只读历史同步，补录平台订单和已实现盈亏。也可以对指定账户手动下达「同步订单与盈亏历史」。插件在限时内滚动历史表格，为 Live 账户读取 Portfolio 出金记录，按每行完整来源账户名归属。回执提供读取数、跳过行数和是否到达已加载数据末尾。中心离线时桥保留读数和待补历史的标记，恢复后续传。

## 从共享策略版本升级

升级已有分布式节点时，先更新中心，再通过「服务器 → 下达更新」选择节点和目标 Git 提交。节点脚本安装桥和插件，并向中心回报实际版本。手动加载的节点需要重新加载插件。开仓前实读风控需要本版节点桥和 1.9.0 或更高版本插件。「服务器 → 浏览器」显示插件实际上报版本及其与中心所附插件的比较结果。插件弹窗也显示本机加载版本。[受管节点安装与更新](deploy/UPDATES.md)

备份原 SQLite 库，更新并重启中心与各节点桥，让反向代理转发新增的 `/v1/ledger` 和 `/v1/logs`。在浏览器扩展管理页重新加载本项目的插件，刷新已登录的 NQ 交易页并重新绑定。旧库中的成功资金回执会补入历史。单节点保留已有运行状态。多节点会继承原策略参数，正在执行的旧批次按指令所属节点跟踪，原批次结束后需在各节点分别启动下一轮。新的节点运行日志从升级时开始记录。

## 离线验证

```sh
python -m unittest discover -s tests -v
node tests/browser-smoke.mjs
```
